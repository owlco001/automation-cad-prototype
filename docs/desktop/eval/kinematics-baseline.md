# 运动学自动识别基线（precision / recall）

评估对象：`desktop/src/cad/kinematics-auto.ts` 的 `suggestKinematics()`。
基线代码：`main@7c3cbf7`，`src/cad/kinematics-auto.ts` sha256 前 16 位 `4cf6bfe50ff36072`。
评估脚本：`desktop/scripts/kinematics-baseline.mjs`（只读，无新增依赖）。

## 1. 结论摘要

数据集：**21 套整机装配**（7 种中文需求 × 3 种命名/导出约定）+ 1 套仓库自带 STEP 夹具，共 1056 个网格、**93 条真值机构**。

| 置信度档 | 预测数 | 严格正确 | 多余项 | precision | 扣真值缺口后 P | recall | F1 |
|---|---|---|---|---|---|---|---|
| ≥0.6（UI「高置信度」） | 64 | 50 | 9 | **78.1%** | **90.9%** | **53.8%** | 63.7% |
| ≥0.8 | 50 | 50 | 0 | 100.0% | 100.0% | 53.8% | 69.9% |
| ≥0.9 | 12 | 12 | 0 | 100.0% | 100.0% | 12.9% | 22.9% |
| 全量（≥0） | 154 | 62 | 61 | 40.3% | 45.6% | 66.7% | 50.2% |

四条可直接用于决策的事实：

1. **识别率几乎完全由「装配里有没有型号」决定。** 型号在零件名（R2）或子装配名（R3）时，≥0.8 档 precision / F1 = **100% / 89.3%**，recall 80.6%，31 条真值机构**一条没漏**（recall@0 = 100%）；只有通用件名（R1，`工位1气缸1 缸体`）时，≥0.6 档 **0 条严格正确**——机构全被找到（31/31 命中），但**行程 31/31 全错**。
2. **高置信度档没有一条真正的误判。** ≥0.6 档的 9 条多余项全部是 `分度转盘 + 转盘治具`——它们确实会转，只是整机生成器没把它们写进 `movingAxes`（真值缺口）。扣掉这部分，≥0.6 档 precision 是 90.9%；再扣掉 5 条"行程未知却给 0.6"的 R1 夹爪，就是 100%。
3. **转盘（dial）布局会吃掉 6 条本来正确的夹爪。** 转盘按工位数分度（3 工位 120°、6 工位 60°），夹爪真实开合方向与最近主轴偏 30°，`snapAxis()` 的偏角惩罚（−0.3）把置信度从 0.8 压到 **0.5**，掉出高置信度档——这是「有型号」场景 recall 只有 80.6% 的唯一原因。
4. **阈值 0.9 是纯损失，0.8 严格优于 0.6。** 0.6→0.8：TP 都是 50 条不变，多余项从 9 降到 0（precision 78.1%→100%）；0.8→0.9：precision 不变，recall 从 53.8% 掉到 12.9%。0.9 只留下 12 条"型号 + 同轴 + 回转体 + 行程 + 层级"全中的气缸。

## 2. 评估口径

- **单位：机构（一条可动轴）**。一个气缸即使被拆成 3 条建议，对真值也只算 1 条机构。
- **匹配**：预测建议与真值机构按「重叠网格数」贪心 1:1 匹配（至少 1 个网格重叠），先大后小、再按置信度。
- **严格正确（TP）**：类别一致 + 方向一致 + 行程一致。
  - 方向：夹角 ≤20°；直线机构还要求正负号一致（伸出方向）；旋转/夹爪只看轴线（正负号无物理意义）。
  - 行程：`|预测 − 真值| ≤ max(1 mm, 5%)`；旋转按角度 5%；夹爪按**单指行程**（= 生成器双指合计行程 / 2）。
- **分档**：≥0.6 / ≥0.8 / ≥0.9。分子分母只统计该档内的建议，recall 分母始终是全量真值（93），因此能看出提高阈值的召回代价。
- **扣真值缺口后 P**：`TP / (该档预测数 − unlabeled-mechanism 多余项)`。只扣"生成器未标注但确实会动"的机构（分度盘、转盘治具、输送线减速电机），不扣真正的误判。
- **网格级**：匹配机构内部 `网格P = 重叠数 / 预测动件数`、`网格R = 重叠数 / 真值动件数`。抓"机构对了但动件集合不对"。
- **误判类型**（命中项可叠加，多余项单一归类）：
  - 角色/类别错、方向错、行程错（命中但某项不一致）；
  - 多余项：`structure`（结构件误判）、`unlabeled-mechanism`（真值未标注的可动机构）、`fragment`（同一机构被拆成的碎片）、`duplicate-split`（同机构重复）；
  - 漏项（没有任何预测与之重叠）。

## 3. 真值从哪来（没有人工标注，也不是我编的）

1. **`machine/geometry.ts` 的 `movingAxes`**：整机生成器摆件时就声明了「哪些零件属于哪条运动轴、轴向量、行程/角度、绑定点位」（`GeomMovingAxis.partIds` / `axis` / `strokeMm` / `rangeDeg` / `points`）。这是仓库内唯一确定性的机构级真值。
2. **配置也是确定性生成的**：中文需求 → `machine/spec.ts` 的 `parseMachineBrief()` → `machine/synth.ts` 的 `synthMachine()` → `MachineConfig`。7 条需求里第 5 条直接取自 `scripts/build-machine-case.mjs` 的真实案例 brief。
3. **几何没有伪造**：生成器输出的是概念占位体（`box` / `cylinder` 两种 `GeomShape`），脚本按同一形状**精确取样顶点**——box 取 8 角点、cylinder 取两端各 16 边形顶点，绕 Z 施加 `rotationZDeg`、平移到 `center`——再喂给 `analyzeMeshShape()`，因此 PCA / 回转体判断走的是 `source: 'vertices'` 的真实分支，不是包围盒兜底。
4. **STEP 夹具单独列**：`test/fixtures/kinematics-assembly.stp` 走 `parseOcctBuffer()` 真解析；4 条真值来自 `scripts/gen-kinematics-fixture.mjs` 的构造注释与 `test/cad/kinematics-auto.test.mjs` 的断言。它是 **in-sample**（同一夹具被单元测试断言），所以**不计入主指标**。

## 5. 误差分析：错在哪、为什么

### 5.1 命中不是问题，行程才是

93 条真值机构**全部**被至少一条建议覆盖（漏项 = 0），≥0.6 档方向一致率 100%。错的是行程：

- **31 条行程错全部集中在 R1（无型号）**：气缸 `0 mm`（真值 40，6 条）、夹爪 `0 mm`（真值 3，11 条）、旋转台 `90°`（真值 180，14 条，取的是 `DEFAULT_ROTATION_RANGE_DEG`）。
- ≥0.6 档 50 条正确建议的行程来源只有两种：`catalog` 38（夹爪/旋转台型号样本表）、`model-code` 12（气缸型号里的行程）；`geometry` **0 条**。"几何估算行程"在这批数据里从未产出一条正确的行程——它要生效，前提是缸体和活塞杆先聚成一簇，而 R1 恰恰聚不起来（见 5.2）。

### 5.2 R1 的根因：同一执行机构的件被拆成多个簇

`buildClusters()` 在没有型号（`seriesKey`）、但件名自带类别关键词时，用 `nameStem()` 作簇键；`nameStem()` 先剥掉件角色词，于是：

```
工位1气缸1 缸体 Ø32×40   → 剥掉「缸体」  → "工位1气缸1  Ø32×40"   ← 一簇
工位1气缸1 活塞杆         → 剥掉「活塞杆」→ "工位1气缸1"          ← 另一簇
```

两个 stem 不再相等，同一个气缸裂成两条建议：缸体被当成"未拆分的整件气缸"单独输出（多余项）；活塞杆单独成一条——它虽然按网格重叠匹配上了真值，但方向取最长轴 `+Z`（真值 −Z，就是 5.1 里那 6 条方向错），行程 0。两条都只有 0.25 分。旋转台同样裂成 `台面` / `底座` / `治具` 三簇——R1 的 20 条 `fragment` + 14 条 `duplicate-split` 就是这么来的。

只要型号出现在**任意一层**（R2 零件名或 R3 子装配名），簇键就变成 `group#型号`，缸体+活塞杆+压头归回一簇，`analyzeCylinder()` 的同轴判定生效，得分 0.9。**R2/R3 与 R1 的差距主要就是这一条。**

### 5.3 转盘布局：正确方向被判「偏轴」，夹爪掉到 0.5

`dial` 布局把每个工位整体绕 Z 分度（3 工位 120°、6 工位 60°）。夹爪开合方向随之变成 `[0.5, ±0.866, 0]`，与最近主轴（Y）偏 **30°**；`snapAxis()` 的惩罚 `-min(0.3, 30/100) = -0.3` 把 0.8 压到 **0.5**，于是 6 条本来正确的夹爪掉出高置信度档：3 工位机 2 条 + 6 工位机 4 条（与 ±X/±Y 轴对齐的工位不受影响——3 工位只有 0°，6 工位有 0° 和 180°，所以各剩 1 条、2 条留在 0.8）这就是 R2/R3 recall 只有 80.6% 的全部原因（25/31）。

这不是"算错方向"——`directionVector` 保留的是真实方向，判据也是按真值向量算的，所以方向一致率 100%。问题在**打分**：标注层只支持 ±X/±Y/±Z，识别器于是给"非主轴"扣分，但转盘布局里非主轴是**常态**，不是不确定。结果是"越真实的转盘产线，越拿不到高置信度"。

### 5.4 高置信度档的 9 条多余项：真值缺口，不是误判

`dial` 布局的 `分度转盘 + 转盘治具` 被识别成 rotary 0.6 分。它们**确实会转**，但整机生成器的 `movingAxes` 只登记 `ActuatorConfig` 对应的轴，分度盘不在其中。脚本把这类归到 `unlabeled-mechanism` 并给出"扣真值缺口后 precision"，就是要避免把标注缺口算成算法错误：扣掉后 ≥0.6 档 precision 从 78.1% 升到 90.9%。

同样归入这一类的还有 `输送线减速电机`（linear 布局的 3 台机器各 1 个，0.35，落在低置信度档）——它也是会转的，只是没被标注。

### 5.5 机架台面被当成"转盘台面"（真误判，0.5）

`机架台面 680×1460×20`（role `frame`）与 `凸轮分度器` 同处 `MACHINE` 组、包围盒相邻，被 `buildClusters()` 按"table 角色 + 同组相邻"并入分度器簇，`analyzeRotary()` 于是把这块 1.4 米长的机架顶板当成转盘台面输出（0.5 分）。这是**真误判**（脚本归为 `structure`，共 9 条 = 3 个转盘布局 × 3 种约定），好在没进高置信度档。根因是"角色词 `台面` + 相邻即归簇"缺少尺寸/位置合理性校验。

### 5.6 机构判对，但动件集合过宽

≥0.6 档网格 P/R = 89.1% / 86.4%。典型：气缸簇把 `安装块`、`治具` 一起算进动件（该气缸网格 P = 50%、R = 100%），因为"簇内除 body 外都算 moving"，而这些结构件恰好也在同一子装配里。机构级判对、采纳后动件多选两件，现有 `validateDraft` 不检查"动件是否包含结构件"，用户只能肉眼发现。R1 因碎片化反而网格 P = 100%、R = 50%（每条建议只有单个件）。

### 5.7 点位绑定

匹配上的机构点位命中 100%（≥0.6 档）。R1 全量档只有 54.8%——不是匹配逻辑差，而是"同一点位只能绑一条建议"，机构被拆碎后碎片抢不到点位。

## 6. 对「阈值 0.9」的结论

| 阈值变化 | TP | 多余项 | precision | recall |
|---|---|---|---|---|
| 0.6 → 0.8 | 50 → 50 | 9 → 0 | 78.1% → 100% | 53.8% → 53.8% |
| 0.8 → 0.9 | 50 → 12 | 0 → 0 | 100% → 100% | 53.8% → **12.9%** |

- **0.8 严格优于 0.6**：同样的 50 条正确建议，少 14 条噪声（9 条真值缺口 + 5 条行程未知的夹爪）。
- **0.9 没有精度收益**：precision 本来就是 100%，0.9 只是把 recall 砍掉 3/4。0.9 这条线留下的是"型号 + 同轴 + 圆形截面 + 行程 + 层级"全中的气缸（0.35+0.3+0.05+0.15+0.05）。
- 但**不要把 0.8 当作"正确阈值"**：0.6 档比 0.8 档多出来的 14 条噪声里，9 条是标注缺口、5 条是行程未知。真正该修的是两处打分：
  1. **行程未知不该给高置信度**：`travelMm === 0`（线性）或 `strokeSource === 'none'/'default'`（旋转）时压到 0.6 以下。这一步单独能把 ≥0.6 档的预测池从 64 条缩到 59 条、precision 从 78.1% 提到 84.7%（扣真值缺口后 100%），且不损失任何 recall。
  2. **偏轴惩罚不该惩罚"真实非主轴"**：转盘布局里偏角是几何事实，不是不确定。建议对 `offAxisDeg` 只在"坐标系可疑"（如同一机器内方向不一致）时惩罚，或把惩罚减半（0.1 而非 0.3）。修好后 R2/R3 的 recall 可从 80.6% 回到 100%（再 +6 条夹爪）。

## 7. 局限（必读）

1. **只覆盖「生成器的概念占位体」**：box / cylinder 两种形状、标准件按规则摆放、装配变换是绕 Z 的刚体旋转。真实 STEP 的曲面、B-Rep 拓扑、非单位阵装配变换、坐标系不一致，本基线一条都没覆盖。
2. **客户 STEP 的代表性有限**：R2/R3 只模拟了"名称里有型号"这一种有利情况。真实导出常见的名称缺失、件名乱码（`Part1`/`Body2`）、同一型号多实例、装配层级被压平，都没进样本；R1 是它们的近似上界，而 R1 的严格正确率是 0。
3. **真值偏"理想"**：`movingAxes` 只标注工艺机构的轴；分度盘、输送线、门的开合等真实可动件未标注（已单列为 `unlabeled-mechanism`）。所以本基线的 recall 是"对工艺机构的召回"，不是"对全部可动件的召回"——高置信度档的 9 条"多余项"正是这个缺口的直接体现。
4. **R1 的 180° 是数据集设定**：三种约定共用 MSQB20A 的 180°，识别器在无型号时默认 90°，因此 R1 的 14 条旋转行程错属于"信息缺失 + 默认值静默"，不等于算法缺陷；气缸/夹爪的 0 行程同理（这些器物本身不带行程信息）。
5. **STEP 夹具是 in-sample**：`test/cad/kinematics-auto.test.mjs` 断言的正是这份夹具，4/4、网格 P/R 100% 只能说明"没退化"，不能当泛化能力。
6. **样本量与姿态**：93 条机构、7 种需求；气缸只覆盖"竖直安装、向下伸出"（生成器固定摆法），滑台/丝杆机构根本不在样本里（整机生成器不产出这两类），R1 里也因此看不到这两类机构的失败模式。

## 8. 客户 STEP 的最小可行评估集（要人标注，必须承认）

`occt-import-js` 只给网格名 + 装配路径，**没有语义**：它不会告诉你哪个件动、沿哪个轴、行程多少。客户 STEP 的真值只能由懂工艺的人标注，这一点无法自动化。

**规模**

| 项 | 数量 | 理由 |
|---|---|---|
| 真实客户 STEP 装配 | 10 套 | 装配 2 / 锁螺丝 2 / 包装 2 / 输送线 2 + 无型号或压平导出 2（专测召回下限） |
| 每套机构数 | 8–15 | 与本次 93 条的统计稳定性相当，合计 100–150 条 |
| 标注人 | 2 人独立 + 1 人裁决 | 抽 20% 交叉复核，机构级一致率 ≥95% 才可用 |

**每条机构要标的字段（JSONL，一行一条）**

```json
{"assembly_id":"cust-001","step_sha256":"…","mechanism_id":"M3","kind":"linear",
 "part_paths":["ST1/CYL_A1/CDJ2B16-50/活塞杆","ST1/CYL_A1/CDJ2B16-50/压头"],
 "axis_vector":[0,0,-1],"direction_sign":-1,"travel_mm":50,"io_point":"ST1-EXT-A1",
 "expected_level":"high","annotator":"A","notes":"竖直向下压装"}
```

- `kind`：linear / gripper / rotary（与 `GeomMovingAxis.kind` 同口径）。
- `part_paths`：**装配路径 + 件名**，不用 mesh id（occt 导入顺序不稳定）；脚本按 `name + path` 反查 mesh id，同名件靠 path 消歧。
- `travel_mm` / `range_deg`：填真实行程；未知填 `null`，评估时单列"行程未知"子集，不计入行程正确率。
- `expected_level`：标注人认为**应当**是 high / low / none（用来检查"什么该给高置信度"，而不只是打分）。

**判据**（沿用本次口径）：≥0.6 档 precision ≥95%（按扣真值缺口口径）、recall ≥70%、高置信度档真正的误判（`structure`/`fragment`/`duplicate-split`）为 0。
**成本**：每套 15–30 分钟（10–15 条机构），10 套约 4–6 人时；脚本改造约 1 天（加 `--cases=<dir>` 读 JSONL，替换内置生成器数据源）。
**脚本已就绪的部分**：匹配、严格正确判定、分档、误判分类、网格级与点位指标都与数据源解耦，只需替换 `machineCase()` 这段喂入。

## 9. 如何重跑 / 如何加样本

- 重跑：`cd desktop && node scripts/kinematics-baseline.mjs`（工作树干净时）；`--json` 取机器可读结果，`--json=path` 落盘。
- 源码隔离：`KIN_BASELINE_SRC=<dir>` 指定源码目录。工作树被并发修改时，用 `git archive` 导出干净 src 再跑，数字才对得上确定的代码状态（脚本会打印 `kinematics-auto.ts` 的 sha256 前 16 位，并提示工作树是否脏）。
- 加整机样本：在脚本 `BRIEFS` 里加一条中文需求即可（自动走 `parseMachineBrief` → `synthMachine` → `generateMachineGeometry`，真值自动带出）。注意 `synthMachine` 的 id 必须是 `design-<process>-<n>st`，否则 `geometry.ts` 的 `inferProcess()` 认不出工艺、所有机器会退化成默认 linear 布局。
- 加真实 STEP：实现第 8 节的 `--cases` 读取器；或按 `fixtureCase()` 的写法，用一份 JSONL 真值 + `test/fixtures/` 里的 STEP。
- 回归用法：对比两次 `overall.bands` 即可；`details.matched` / `details.falsePositives` / `details.falseNegatives` 保留逐条记录（机器、真值 id、置信度、轴、`offAxisDeg`、行程、网格名），可直接 diff 出"哪条建议变好/变坏"。

## 10. 2026-11-02 更新：通用件名（R1）几何归组

第一版基线暴露的洞：**R1 档 ≥0.6 严格正确 0/31**。根因不是「名字里没有型号码」这么简单——实测 R1 的零件名是 `工位1气缸1 缸体 Ø32×40` 这类**类别词在、型号不在**，引擎挂在**归组**：`buildClusters` 按名称主干分桶，缸体与活塞杆主干不同 → 各成单件聚类 → 报「气缸只有一个网格」。

修法（`desktop/src/cad/kinematics-auto.ts`）：新增同轴「细杆+粗体」配对（`:858`）、贴杆随动件（`:897`）、镜像两指（`:950`）、旋转台本体/随动判定（`:1032`）、按机构最小件算归组容差（`:790`），以及只在整台装配都认不出机构时才启用的纯几何兜底（`:1113`）。几何来源的置信度**统一封顶 0.65**（`:239`），低于批量门槛 0.8，且 `strokeSource: geometry` 本就被 `batchGate` 挡住——猜出来的东西不会被批量写进标注。

|---|---|---|---|

| ≥0.8 | 0 · — · 0% | 25 · 100% · 80.6%（不变） | 25 · 100% · 80.6%（不变） |

按类别：R1 `cylinder 6/6 · gripper 5/11 · rotary 0/14`。

仍然没解决的（如实记录）：

- **rotary 0/14**：几何分不出 90°/180°/270°，无型号可查时只能预填 90°（真值 180°），已压到 0.55 低置信，不污染高置信档；
- **gripper 5/11**：差在置信度不是识别——六工位机每工位转 30°/60°，而标注层只支持 ±X/±Y/±Z，`snapAxis` 偏 30° 扣 0.3 直接掉到 0.40；要动得改扣分策略或放宽轴向，超出本次范围；
