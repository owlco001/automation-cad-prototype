# PV Buffer workflow software improvements

真实 ds4.1flash 软件智能体设计光伏缓存机时发现并修复：

1. 空白画布 `.cw-empty` 全局绝对定位覆盖检查器关闭按钮，改为只定位 `#cwNodes > .cw-empty`。
2. Agent 写确认卡 z-index低于 Agent 抽屉，实际按钮不可命中导致120秒超时误报 USER_DENIED；确认卡提升到最大层级，容量模型和单塔建模真实允许一次成功。
3. 新增 `analyzeBufferCapacity` 及 `design_machine.buffer`：明确上/下游节拍、停机新增、初始库存、在途、预留、容量、净积料和长期背压警告。
4. 生成器允许严格 `layerPitchMm=180`（原下限250），但既有缓存工程仍实际使用250，重新生成才会采用180。
5. Viewer 新增 `sceneIntegrity()`，显式比较模型零件与场景承载零件；避免工程保存90件、视口仅6件时被误报为完整联调。
6. 完整回归（**历史数字，勿当现状**）3328：3325通过、3跳过、0失败；其后定版回归为 3463 tests / 3460 pass / 0 fail / 3 skipped（HEAD `411f21d`，历史）。**当前未提交工作区（HEAD `411f21d` + 16 M + 3 ??）本轮最终实测**：focused **281 / 281**、全量 **3518 tests / 3515 pass / 0 fail / 3 skipped**（204.3 s）、`tsc --noEmit` **0 诊断**、`build:ext` extension **2,938,104 B** / gzip **918,889 B**、regen `checks=58 failed=0`（8 层 90 件）、project-session-smoke PASS。这些数字**未提交、未上 CI**，不能当已发布状态。
7. 新增 `config.bufferTower` 塔身建造器（`buffer-tower-assembly.ts`）：容量身份与几何入参分离（几何入参改不了塔数/每塔储位）、fail-loud 不夹紧、储位由零件表真派生、塔升降轴行程由几何给。16 层配置出 **146 件 / 设计包络 2430×1790×3840 / 可用储位 15**（静态件表 + AABB，已提交）。
8. **塔的 B-Rep 入口已接通（本轮，未提交）**：`build_machine_model` 支持 `process='buffer-tower'` + 扁平参数，或 `design`/`config`（`design.config.bufferTower` 权威），出 **146 件**逐件 STL + 合并 STEP；`design` 落盘保留 `panel/inbound/frame`；塔分支也走 `resolveMachineGeometry`（地面线守卫 + 随动件标注），两条链件数不一致报 `INTERNAL_ERROR`。
9. **分派判据只留一份（本轮）**：`isBufferTowerConfig` + `resolveModelDispatch`，命令层/渲染层/几何层共用。只给 `design` 不给 `process` → 按塔建（不再静默出 29 件底层线）；显式 `process='conveyor'` + 塔 design → **冲突拒绝**；声明是塔却没 `bufferTower` → 拒绝。命令层白名单补 `design`/`config`（以前 `未知参数：design`）。**本轮再收紧入口边界**：`design`/`config`/`design.config`/`params` 必须是非数组对象；`process` 必须在 `MODEL_BUILDERS` 里（`screw` 等现在命令层 `INVALID_ARGUMENT`、bridge 0 次），且**给了就必须是非空字符串**（`123`/`{}`/`[]`/`'   '`/`null` 以前被静默当「没写」→ 默认 conveyor、`ok:true`、29 件，现在命令层与工具层都 `INVALID_ARGUMENT`、bridge 0 次）；`design` 与 `config` 二选一（脚本 API 也拒）；**塔 + `params` 双源拒绝**；**非塔 design/config 拒绝**（`config.conveyor{lengthMm:6000}` 以前 `ok:true` 却建默认 2000×300 且无提示，现在明说只从 `params` 取）。
10. **整机 STEP 完整性门禁（本轮）**：`spike/build123d/app.py` 的整机合并从「逐件累计布尔并」（16 层 146 件只出 86 实体、顶点 z 只到 3636）改成一次性 `fuse` + 包络/体积自校验 + 失败回退 Compound；新增 `npm run verify:step-tower`（`desktop/scripts/verify-step-tower.mjs`），按「整机 STEP 顶点包络 == 逐件 STL 并集（按端容差）」+ 实体数与件数挂钩 + **合并路径**判，CI 在 `featuretree-geometry` 跑 16 层 + 8 层，**job timeout 75 min**（步骤预算 72 min：安装 ~10 + 装配 10 + 体积 10 + STEP 12 + 缓存塔 20 + AABB 10）。判据本轮再收紧：容差按端取**且只对垂直于回转体轴的方向给半径**、逐件 `solids` 缺失判红、**合并回退即失败**、**build 模式 `merge` 元数据缺失也判红**（以前整条检查会被跳过）、`--file` 模式默认判红（裸 STEP 判不了 fuse/compound 回退）只有显式 `--merge-manifest` 才判，且 manifest 只认**实现并测过的三种形状**（`{merge:{mode,fallback}}` / 扁平 `{mode,fallback}` / 整份 `{stats:{merge:{mode,fallback}}}`，`fallback` 必须是显式布尔）。**本轮真内核最终实测（当前未提交工作区，node v26.7.0）**：16 层 **146 件 / STEP 2,301,982 B / 104 solids / 812 faces / mode=fuse / 9/9 PASS**；8 层基线 **90 件 / 1,622,322 B / 55 solids / 538 faces / 9/9 PASS**；旧整机 `verify:step`（85 件）**7/7**。**容差口径（上一版把语义写反，已更正）**：两规模下 STEP 顶点包络与逐件 STL 的 Y 上界差均为 **19.99 mm**，来源是 **Ø40 竖直（轴 Z）升降导柱的径向母线**（B-Rep 顶点只落在圆柱接缝 y=780，真实外形到母线 y=800，差 = 半径 20），判据只在**垂直于该轴**的 x/y 方向给 20 mm，**沿轴的端面严格 ±1 mm**——不是「水平圆柱端点 20 mm 容差」。这是「声明容差内通过」，**不能宣称逐点完全一致，也不是制造验收**。**判别力边界**：证据是包络/数量级（顶点并集、实体数下限 `ceil(件数×0.6)`、逐件 bbox、合并路径），**不是逐件身份**——内部件丢失只要不动轴极值且丢后实体数仍在下限之上就看不见（16 层 floor 88 / 实测 104，可丢 16 个实体；8 层 floor 54 / 实测 55，**只丢 1 个实体仍绿**）。**CI 尚未跑过本轮工作区。**
