# Core 本地项目工作区

独立 Core runtime 提供受限的本地项目工作区：可以新建项目、查看本机列表、打开项目，并保存项目名称与备注。数据采用版本 1 JSON schema，不依赖远端服务。

## 保存与安全边界

项目只写入应用专用数据目录下的 `projects/` 子目录。页面只能传项目 ID、名称和备注，不能指定文件名、目录或任意路径；主进程只注册列表、新建、打开、保存四个项目 IPC。Core preload 不暴露通用 IPC、Node 或文件系统对象。

保存前会验证固定字段集合、schema 版本、UUID 项目标识、名称和备注长度，以及时间戳格式。写入时先在同目录建立权限受限的临时文件、同步文件内容，再以原子替换提交；提交前发生失败时会清理临时文件并保留已保存版本。遇到损坏或未知版本文件时，打开、列表或保存会报错，不会自动覆盖它。

## 可选模块目录原型

Core 界面增加可选模块列表、勾选和“下载所选到暂存区”入口。目录来源是主进程内的固定配置，renderer 不能输入 URL 或路径；当前生产配置为空，所以 UI 明确显示目录未配置且不会联网。测试只访问 127.0.0.1 回环 mock。

如果未来经过审核后配置固定 HTTPS 来源，主进程会先验证目录 schema、模块 ID/版本、Core API、依赖/声明能力、大小与 unsigned/blocked 标记，再按目录项派生包地址。ZIP 的总体大小和 SHA-256、文件清单、内部 manifest、ID/版本、兼容范围及入口文件大小/hash 都会复核；响应重定向、超限、截断或内容编码不合策略时会拒绝。单包最多 50 MiB，暂存总量最多 250 MiB、最多 100 包，目录最多 1024 项；并发下载串行处理。有效 ZIP 只原子保存到应用数据目录 `module-staging/`，不会写出解压文件，也不会导入或执行模块。SHA-256 仅检查意外损坏，不等于签名或发布者认证。unsigned 包保持不可信，激活一直被阻止。

现已增加按已暂存包的模块 ID/版本清理单个已下载 ZIP 缓存包的操作，以释放暂存缓存空间。staging 必须显式启用且目录安全；主进程重新验证包，仅删除该 ID/版本唯一对应的普通 ZIP 文件，完全离线，不接收文件路径。它只是 cache cleanup，不是模块卸载，不删除、迁移或修改项目数据及其他包；不解压、安装、更新、执行或激活模块。包仍未签名且不可信，激活仍被阻止；生产目录源仍未配置。

该功能目前只是空生产源下的安全原型，不构成可用的生产模块商店：没有生产 feed、签名信任根或 Windows installer，无法取得真实目录/模块；也没有安装、更新、卸载、权限授予或数据迁移能力。

## Core 只读 CAD 预览与项目附件

独立 Core 页面提供原生文件对话框和专用 three.js 视口，支持 STL 二进制/ASCII 与有限的 GLB 2.0 静态、未纹理三角网格子集。GLB 必须以内嵌单一 buffer 提供网格；外部 URI、扩展、纹理、动画、蒙皮/骨骼、稀疏 accessor 与非三角形图元会拒绝。**STEP/STP、IGES 和其他扩展不支持。**单文件最多 32 MiB、500,000 个三角形、1,000,000 个顶点；视口仅可旋转、平移、缩放和适配模型。

原有“打开 STL / GLB”仍是临时只读预览，不持久化；用户也可以点击“添加 STL / GLB 附件”，但必须先新建项目或从本机项目列表明确打开一个项目。当前项目名与 ID、附件名/大小/摘要和预览入口显示在页面中；没有当前项目时添加按钮禁用。用户选择文件后，主进程再次验证路径、普通文件类型、扩展名、大小及稳定读取，并在写入前运行同一受限 STL/GLB 解析器。取消、解析、复制或索引提交失败不会改变现有附件索引或项目元数据；主进程通过 SHA-256 校验并读取持久化附件，renderer 不得提交路径或自报“解析成功”。

附件与 `projects/<UUID>.json` 中既有项目名称/备注 schema v1 完全分离，附件索引单独存于应用数据 `projects/<UUID>/attachments/index-v1.json`，对象路径只由已校验 UUID 与 64 位小写 SHA-256 派生。索引是版本化 schema v1，只记录 hash、允许的 `.stl`/`.glb` 扩展名、显示名、字节数和时间戳；不记录原始源路径。对象创建使用同目录权限受限临时文件、写入 `fsync` 和排他 hard-link 发布，不覆盖已有对象；重复 hash 会复用同一对象并保留既有元数据。新索引先写入并同步临时文件，再在同目录原子建立或替换，提交失败时旧索引保持不变；该保证针对同目录原子操作与普通写入失败，不等同于断电后的目录项持久性（父目录未单独 `fsync`）。Core 获取 Electron 单实例锁，主进程只创建一个 store 实例，项目锁序列化该实例内同一项目的“读索引—合并—提交”；不声称是通用跨进程锁。失败后未被索引引用的内容对象只作为不可见孤儿保留，不自动删除；没有覆盖、替换或删除附件的 UI 操作。重开附件会检查普通文件、大小、SHA-256 并重新解析，再交给视口。

持久化 IPC 仅能由可信 Core 页面调用；“添加”只接收项目 ID，随后由主进程弹出系统选择器；“打开”只接收项目 ID 和经格式验证的摘要，不接收文件路径。文件读取优先采用 `O_NOFOLLOW`，并对同一已打开句柄校验文件身份和稳定性。页面 CSP `connect-src 'none'`，不访问网络。原文件不会修改；附件只是原始字节的不可变只读副本，不编辑/另存 CAD，不创建 CAD 几何，不应用项目档案，不执行可选模块，不连接 PLC。

Core `app.asar` 白名单仍只有既有 9 个独立运行时文件：附件实现被打包进 Core 主进程 bundle，不加入项目用户数据或额外代码文件。实际打包 smoke 覆盖合成 STL 添加、按摘要从存储重开预览、畸形 GLB 在解析阶段拒绝且附件索引/项目元数据保持不变、源 fixture 字节未改变及外部资源请求为 0。此增量不改变 `installable: false`、unsigned 模块不可信/不可激活、生产 feed/信任策略未配置或无 Windows installer 的状态。

## 能力声明与验证

`project-store-local-only` 只表示本机项目元数据和受限 CAD 只读附件通过本地离线路径测试；不代表 CAD 建模、PLC、Agent、同步或完整设计流程离线可用。Core 仍标记为 `installable: false`，当前 Linux x64 unpacked 包仅用于 Electron 隔离验证，不是可交付 Windows 安装器。

Linux Core smoke 会通过实际 Electron 页面调用创建、保存、列表和重新打开流程；附件 packaged smoke 另外验证先选项目、添加与按摘要重开 STL、畸形 GLB 失败关闭、源文件字节与既有项目/附件状态保持；也检查模块目录未配置时不发网络请求、没有 URL 输入框且下载按钮禁用。独立包 smoke 从新建隔离目录中的实际 Electron 可执行文件运行。单元测试覆盖项目 schema、附件解析/复制/索引故障注入、SHA-256 去重与完整性、危险 ID/摘要拒绝、并发保存和未知版本保护，以及 loopback 模块下载、目录/包校验、重定向拒绝与暂存不解包。

Core 的离线范围包括本机项目元数据、受限 CAD 附件和 STL/有限 GLB 只读预览；不包括 CAD 建模、STEP/IGES、PLC、Agent、同步或完整设计流程。P2 仍需完成 Core 目标系统安装/交付、正式 feed 与签名/信任策略、数据保留和回滚设计，以及发布所需 CAD 工作区能力；远端模块代码执行保持关闭。P1 PLC 同步仍只是本机 mock 合同测试，没有真实 PLC 或智慧工厂服务器联调。便携工程档案恢复仍限于只读候选，几何安全重绑定和原子事务回滚未验收。
